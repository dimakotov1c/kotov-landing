# Динамический блок «Последние видео с YouTube» — снят с сайта

**Дата снятия:** 30 июня 2026
**Статус:** отключён, ждёт надёжного решения

## Что это был за функционал

В секции «Контент» (`<section id="content">`) над блоком «Главные каналы» стояла
сетка из 3 карточек — **три последних видео с YouTube-канала @top_1c**, которые
подгружались автоматически при каждом открытии страницы:

- обложка видео (`https://i.ytimg.com/vi/<VIDEO_ID>/mqdefault.jpg`)
- название
- дата публикации
- ссылка на видео
- при выходе нового видео список обновлялся сам, без правок кода

### Как было реализовано
- Канал: `YT_CHANNEL_ID = 'UCR90x4LTVrYm54jXV6AO1Yw'` (@top_1c)
- RSS-фид YouTube: `https://www.youtube.com/feeds/videos.xml?channel_id=<ID>`
- Браузер не может читать фид напрямую (нет CORS-заголовков у YouTube),
  поэтому шли через бесплатный прокси-конвертер:
  `https://api.rss2json.com/v1/api.json?rss_url=<encoded feed>`
- JS брал первые 3 элемента `items`, рисовал карточки, при ошибке — заглушку «Смотреть видео →»

## Почему сняли

**30 июня 2026** превью перестали грузиться — у всех посетителей, не только при
доступе из-за рубежа. Диагностика (`curl` с сервера вне Вьетнама) показала:

- `api.rss2json.com` → `status:error, "Feed could not be converted"` — **для любого**
  YouTube-канала (проверяли в т.ч. Google Developers) → проблема не в нашем канале
- Прямой фид YouTube отдаёт `404/500` на «серверные» (датацентровые) IP
- Альтернативные прокси тоже не работают: allorigins → 500, corsproxy.io → 403, thingproxy → таймаут

**Вывод:** YouTube начал блокировать доступ к RSS-фиду с датацентровых IP, а все
бесплатные CORS-прокси крутятся именно на таких IP. Бесплатная прокси-схема
стала нерабочей.

## Идеи решения (на будущее)

### Вариант A — YouTube Data API v3 (рекомендованный, надёжный)
- Официальный API Google, отдаёт CORS-заголовки, не блокируется
- Нужен бесплатный API-ключ (Google Cloud Console → Enable "YouTube Data API v3" → Create API key)
- Ключ браузерный/публичный → **обязательно ограничить по HTTP-referrer на `kotov.top`**,
  иначе им смогут пользоваться чужие сайты и выжечь квоту
- Квота 10 000 единиц/день бесплатно — с запасом
- Запрос последних видео:
  `https://www.googleapis.com/youtube/v3/search?key=<KEY>&channelId=<ID>&part=snippet&order=date&maxResults=3&type=video`
- Обложку можно строить из videoId как раньше, либо брать из `snippet.thumbnails`

### Вариант B — статичные 3 видео (запасной)
- Зашить вручную в HTML id/название/дату трёх свежих видео
- Всегда работает, грузится мгновенно
- Минус: обновлять руками при выходе нового видео
- Последние известные видео (на 25 июня 2026):
  - `GZN-0vKbWJ0` — «Менеджеры продаж больше не нужны? Торговый бот выходит на смену» (25 июня)
  - `egONE6r1-bo` — «Новости недели про 1С от 17 июня 2026» (18 июня)
  - `OR3Py7lIdXA` — «Новости недели про 1С от 10 июня 2026» (11 июня)

### Вариант C — серверный кэш (если появится бэкенд)
- Своя функция (Cloudflare Worker / Vercel / VPS) раз в час тянет фид и кэширует JSON
- Сайт ходит к своему эндпоинту → быстро, надёжно, без чужих прокси
- Требует хостинга с серверной частью

## Что осталось в коде
- CSS-классы карточек видео (`.video-card`, `.content-grid`, `.video-skeleton`,
  `.video-thumb*`, `.video-play`, `.video-platform`, `.video-info`, ...) **оставлены**
  в `<style>` — пригодятся при восстановлении функционала
- Заголовок секции изменён на «Где меня читать и смотреть»
- Весь JS-блок загрузки видео (rss2json) **удалён**
